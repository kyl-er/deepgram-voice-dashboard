## Authentication

There is none, on purpose: the server binds to `127.0.0.1`, and the Deepgram key is added server-side. The browser never sends a key.

## Choosing a key

Every proxy route accepts `?key=secondary` to use `DEEPGRAM_V2_API_KEY`. It falls back to the primary key when the secondary isn't set.

## Pass-through behavior

| Route | Query params forwarded |
|---|---|
| `/api/stt` | **all** of them, to `/v1/listen` |
| `/api/tts` | all, plus `model` (default `aura-2-thalia-en`) |
| `/api/read` | only `summarize`, `sentiment`, `topics`, `intents`, `language`, `custom_topic`, `custom_intent` |

Responses from Deepgram (including error status codes) are returned unchanged.

<Tip>
The playground calls `localhost:8787` from your browser. Start the server with `npm start` and the "Send" button on each endpoint page works against your real Deepgram account.
</Tip>
