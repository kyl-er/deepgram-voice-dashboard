## Flat config in, Deepgram Settings out

You work with a flat config object (the shape of `DEFAULT_CONFIG`). The builders turn it into Deepgram's nested Settings message. Any key you omit falls back to `DEFAULT_CONFIG`.

<CodeGroup>
```js Input
buildSettings({
  listenModel: 'nova-3',
  thinkProvider: 'anthropic',
  thinkModel: 'claude-haiku-4-5',
  speakModel: 'aura-2-thalia-en',
  tags: 'demo,office',
});
```

```json Output (abridged)
{
  "type": "Settings",
  "tags": ["demo", "office"],
  "experimental": false,
  "mip_opt_out": false,
  "flags": { "history": true },
  "audio": {
    "input": { "encoding": "linear16", "sample_rate": 24000 },
    "output": { "encoding": "linear16", "sample_rate": 24000, "container": "none" }
  },
  "agent": {
    "listen": { "provider": { "type": "deepgram", "model": "nova-3", "version": "v2", "language": "en", "smart_format": false } },
    "think": {
      "provider": { "type": "anthropic", "model": "claude-haiku-4-5", "temperature": 0.6 },
      "prompt": "You are a terse, precise voice operator with real tools. …",
      "functions": [ { "name": "end_call", "description": "…", "parameters": { … }, "defer_until_eot": true }, … ]
    },
    "speak": { "provider": { "type": "deepgram", "model": "aura-2-thalia-en", "speed": 1 } },
    "greeting": "Channel open. What do you need?"
  }
}
```
</CodeGroup>

## Functions

<ResponseField name="buildAgentConfig(cfg)" type="object">
  Returns just the `agent` half (`listen`, `think`, `speak`, `greeting`, optional `context`). This is what the SDK's `agent:` option takes inline. Applies the [Flux vs Aura rules](/concepts/voice-agent#flux-vs-aura-the-rules) and attaches `functionDefs()`.
</ResponseField>

<ResponseField name="buildSettings(cfg)" type="object">
  Full `Settings` message: `tags`, `experimental`, `mip_opt_out`, `flags.history`, `audio` input/output, and `agent`. Send this first on a raw socket.
</ResponseField>

## SCHEMA
